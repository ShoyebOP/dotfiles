# Feature Research

**Domain:** Dotfiles / Stow-based development environment bootstrapper (GNU Stow 7 packages, Neovim lazy.nvim, Zsh/Zinit/P10k, desktop primitives)
**Researched:** 2026-09-10
**Confidence:** HIGH (table stakes & core installer — validated against PROJECT.md + 6 codebase maps + live repo), MEDIUM (differentiator UX polish — inferred from 44-plugin Neovim + Zsh 391-line rc)

## Feature Landscape

### Table Stakes (Users Expect These)

Features users assume exist. Missing these = product feels incomplete; users leave or fall back to manual `stow`.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| **One-command clone → working env** (`bash setup.sh` → Zsh + Neovim + desktop) | Core value in PROJECT.md. Every dotfiles README promises `git clone && ./install`. If manual `stow` steps are required, bootstrapper has failed. | MEDIUM | Unified Bash entry `setup.sh`/`install.sh` with `--install`/`--uninstall` (`--remove`) flags; replaces 4-script matrix (`setup.nu`/`setup.zsh`/`teardown.*`). Must be Bash — preinstalled on Arch/CachyOS/Ubuntu minimal images (PROJECT.md constraint). Keep flags ergonomic: `--mode local|server`, `--dry-run`, `--stow-keyd y/n`, `--help`. Implement `set -euo pipefail` + `shopt -s inherit_errexit` (Bash 5.2). Run ShellCheck 0.10.x in self-test. |
| **Dry-run preview before any write** (`--dry-run`) | Table stakes for any installer that touches `$HOME` and `/etc`. Users cited in CONCERNS.md will not run it in a VM without preview. Existing `setup.nu`/`setup.zsh` already have it — removing regresses trust. | LOW | Use `stow --no --verbose` for symlink preview; print `sudo stow --adopt -t / keyd` as `[DRY RUN]` string without exec; print `pacman -S`/`apt install` commands; preview `chsh` change and `~/.local/share/zinit` clone. Must be first-class — every mutating path guarded by `$DRY_RUN` early return. Self-test should also run `--dry-run` headlessly. |
| **Reversibility / clean uninstall** (`--uninstall`/`--remove` parity with install) | PROJECT.md reversibility constraint. Users expect `teardown` parity in one binary. Without it, testing in VM or moving machines risks orphan symlinks + stale `/etc/keyd/default.conf`. | MEDIUM | Implement `stow -D` for core (`nvim`,`zsh`,`starship`) + GUI (`alacritty`,`wofi`,`hyprland`) + `sudo stow -D -t / keyd`. Remove Mason artefacts when Neovim package is uninstalled (see Mason auto-install row). Require exact `yes` confirmation for destructive path (existing `Type 'yes'` pattern), bypassable via `--yes`/`--force` for CI. No snapshot yet — document limitation (see Anti-features). |
| **Non-crashing distro detection (derivatives + package-manager probe)** | #1 crash cause per CONCERNS.md: hard-coded `["arch","cachyos","ubuntu"]` rejects Manjaro/EndeavourOS/Mint/Pop!_OS with `Error: This script only supports…` even though package manager is compatible. Users hit this on first run. | LOW | Fix: `source /etc/os-release` → inspect `ID` + space-separated `ID_LIKE` + probe `command -v pacman`/`apt`/`apt-get`. Bash idiom: `[[ $ID == arch ]] \|\| [[ " $ID_LIKE " == *" arch "* ]] \|\| command -v pacman &>/dev/null`. Priority: probe package manager first, fall back to `ID_LIKE`. Map Arch-family → `pacman -S --needed`, Debian-family → `apt install -y`. Verify post-install with `verify-deps` re-run (currently missing). Document supported matrix in README table. Per-distro core/GUI dep lists must be corrected (existing `common=[stow,nvim,starship,git,zoxide,uv,rg,node,npm]` hard-coded vs GUI lists diverging between Nushell/Zsh). |
| **Dependency verify → install → re-verify loop (with locking)** | Users expect installer to tell them what's missing and offer to install. Current `verify-deps` collects `missing` but `install-deps` lacks post-verify and has no lock/pin. Partial installs silently succeed. | MEDIUM | Steps: `verify_command` (`command -v`/`which`), partition `core` vs `gui` missing, prompt `Install ALL / CORE only / Skip / Select`, run `sudo pacman -S --needed` or `sudo apt install -y`, then **re-run `verify-deps`** and abort with report if still missing. Add `make`+`gcc` to `common` for server mode (fixes `telescope-fzf-native` silent `cond = executable("make")==1` fallback). Detect non-interactive TTY (`[[ ! -t 0 ]]`) → auto-install core, skip GUI (already in `setup.zsh` — keep). No version pinning needed for apt/pacman in this milestone — log installed versions for audit. |
| **Shell binary self-install before stowing shell config** | PROJECT.md: installer installs chosen shell itself. Minimal server images ship without `zsh`; stowing `zsh/.zshrc` then launching `zsh` crashes. Current `setup.zsh` assumes `zsh` present — bootstrap paradox. | MEDIUM | Detect `command -v zsh` before stow. If missing: `sudo pacman -S --needed zsh` / `sudo apt install -y zsh`. Then ensure Zinit: `[[ -d ~/.local/share/zinit/zinit.git ]] \|\| git clone https://github.com/zdharma-continuum/zinit ~/.local/share/zinit/zinit.git` (commit-pinned). Then `stow --restow zsh`. Offer `chsh -s $(which zsh)` after `which zsh \| sudo tee -a /etc/shells` with explicit `read -q` confirmation — **never auto-chsh** (anti-feature). For Nushell backup path, same check but skip fixes. |
| **Stow symlink correctness + conflict detection** | Fragile area per CONCERNS.md: `starship/.config/starship.toml` folding, `keyd/etc/keyd/default.conf` → `/etc/keyd/default.conf`, repo moved/subdir invocation. Silent wrong symlink renders prompt/theme broken with no error. | LOW | Use `stow --no --verbose` to preview; check `[[ -e ~/.config/starship.toml ]] && [[ ! -L ~/.config/starship.toml ]]` before `rm -rf` (existing guard) — but surface conflict explicitly: `echo "! WARNING: ~/.config/starship.toml is real file; backup or skip?"` then `read`. Assert invocation dir is repo root (`[[ -f ./setup.sh ]] \|\| { echo "Run from repo root"; exit 1; }`). Post-stow verification: `ls -la ~/.config/nvim/init.lua` is symlink → repo. Self-test validates all 7 packages' targets. Document `stow --restow` idempotence in README. |
| **Privileged `/etc/keyd` safety (no silent `--adopt`)** | Security concern per CONCERNS.md: `sudo stow --adopt -t / keyd` moves host file into repo, then `keyd reload`+`systemctl`. If `keyd/etc/keyd/default.conf` malicious or stale, input handling is hijacked. Current mitigation is only dry-run preview. | MEDIUM | Replace raw `--adopt` with: `stow --no --verbose -t / keyd` conflict check first; if conflict → show `diff`/`cat /etc/keyd/default.conf` vs repo file, require typed `yes`. Use plain `sudo stow -t / keyd` when no conflict; only use `--adopt` after explicit user consent with warning "moves existing /etc/keyd/default.conf into repo". Reload via `sudo keyd reload` + least-privilege sudoers (`shoyeb ALL=(ALL) NOPASSWD: /usr/bin/systemctl start keyd, /usr/bin/systemctl stop keyd, /usr/bin/systemctl reload keyd`). Document in README. |
| **Idempotent re-runs** | Dotfiles installers are run repeatedly after `git pull`. Users expect second run is no-op or clean `--restow`. Current stow path is idempotent, package installs not. | LOW | Ensure `stow --restow` everywhere (not `stow` alone). `pacman -S --needed` already idempotent; `apt install -y` is. Gate `uv generate-shell-completion zsh > ~/.config/zsh/completions/_uv` with `mkdir -p` + overwrite. Mason auto-install must be deduped (`deduplicate()` already in `lang/init.lua`). |
| **PATH dedup + stable ordering** | Scaling limit per CONCERNS.md: `~/.local/bin`, `~/.local/sbin`, `~/.cargo/bin`, `~/.bun/bin`, `~/.npm-global/bin`, `~/.local/share/zinit` prepended in both `env.nu`+`zsh/.zshrc` → 10+ segments, duplicates after reload, `ARG_MAX` risk, slow completions. | LOW | In `zsh/.zshrc`, replace repeated `export PATH="$HOME/.xxx:$PATH"` with deduped array: `typeset -U path; path=(~/.local/bin ~/.local/sbin ~/.cargo/bin ~/.bun/bin ~/.npm-global/bin $path); export PATH`. Keep `BUN_INSTALL` contract. In Nushell equivalent (backup), use `str uniq` filter — but do not fix Nushell beyond docs per scope. Verify in self-test: `echo $PATH \| tr : '\n' \| sort \| uniq -d` must be empty. |
| **Neovim LSPs work without manual `:MasonInstallAll`** | Current pain per PROJECT.md: python `pyright`/`ruff` etc. don't work after setup without manual `:MasonInstallAll`. Modern distros (LazyVim, kickstart) auto-install — users assume it. | MEDIUM | Table stakes for editor completeness. Implement Mason auto-install on setup (see Differentiator row for detail) but **presence** of auto-install is table stakes — mechanism can be phased. Minimal v1: `nvim --headless -c "MasonInstallAll" -c "qa"` invoked by `setup.sh` after stow when `mode != dry-run` and `nvim` present. Guard with timeout + `mr.refresh` callback. |
| **Basic docs reflect reality (Zsh default, Bash entry, ignore Nushell-favoring)** | PROJECT.md requires docs updated everywhere to Zsh default, Nushell backup, new Bash usage (`README.md`, `nvim/README.md`, in-code comments). Current README still shows `nu setup.nu` / `zsh setup.zsh` as primary — new users follow stale table. | LOW | Update README "Choose your shell path" → "Default: Zsh (Backup: Nushell)" with `bash setup.sh --mode local` primary, `bash setup.sh --mode server --dry-run` examples, manual `stow --restow nvim zsh starship` vs `nvim nushell starship`. Add `nvim/README.md` note, `zsh/.zshrc` header, and a project instruction file (AGENTS.md/CONVENTIONS.md) guidance. Keep Nushell rows but mark backup. |

### Differentiators (Competitive Advantage)

Features that set the product apart. Not required for bare function, but why this dotfiles feels polished vs raw `stow` repos.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Interactive TUI checklist — mode → shell → package override before writes** | PROJECT.md specified flow: mode (`local` full GUI vs `server` headless) → shell (`zsh` default / `nushell` backup) → build package list → **select/deselect checklist manual override** → execute. No other Stow dotfiles offer a "shopping-cart" confirmation — users gain confidence on headless vs GUI mismatch and can deselect `keyd`/`hyprland` on server-with-GPU edge cases without editing code. | MEDIUM | Primary: `charmbracelet/gum` ≥0.15.0 `gum choose --no-limit --header "Select packages (Tab to toggle)"` + `gum confirm`. Single static Go binary; `pacman -S gum` / charm apt repo / `go install`. Fallback chain when gum absent: `whiptail --checklist` (preinstalled Ubuntu, fd swap `3>&1 1>&2 2>&3`, returns `"nvim" "zsh"` quoted tags) → `dialog` → plain Bash `select` loop. PACKAGES manifest drives list: `core=[nvim,zsh,starship]` always ON; `gui=[alacritty,wofi,hyprland,waybar,grim,slurp,wl-clipboard]` ON only if `mode==local`; `privileged=[keyd]` OFF by default requiring explicit toggle. Must run **after** mode+shell prompts but **before any write** (safety constraint). Non-interactive (`[[ ! -t 0 ]]` or `--mode` passed + `--yes`) skips checklist with defaults. |
| **Unified Bash single-binary (install + uninstall) eliminating 4-script drift** | Current drift is documented: `setup.nu core=[nvim,nushell,starship]` vs `setup.zsh core=[nvim,zsh]` vs `teardown` lists diverging; bug fix in one doesn't propagate. A single `setup.sh` with `get_distro`/`get_deps`/`verify_deps`/`run_stow`/`run_unstow` sourced from one `manifest` removes the class of bugs. Users run one command regardless of starting shell. | MEDIUM | Canonicalize on Bash 5.2: `get_distro()` sources `/etc/os-release`, `get_deps(distro,mode,shell)` returns arrays via `printf '%s\n'`, `verify_deps`, `install_deps`, `run_stow`, `run_unstow`, `get_mode_interactive`/`get_shell_interactive`/`checklist` functions. Keep `setup.zsh`/`setup.nu` as thin shims that `exec bash setup.sh` for one release, then deprecate. Extract per-distro/package lists to `packages.json` or `deps.toml` if desired — declarative manifest consumed by installer (CONCERNS.md suggestion). |
| **Machine-local gitignored overrides auto-sourced if present** | PROJECT.md explicitly requires `zsh/.zshrc.local` / `~/.zshrc.local` and `nvim/.config/nvim/lua/local.lua` pattern. Solves multi-machine pain (work laptop PATH/alias/theme vs home server) without dirty git. Most dotfiles either commit machine files or tell users to manually patch — auto-sourced ignored files are the elegant middle ground. | LOW | Implement: `[[ -f ~/.zshrc.local ]] && source ~/.zshrc.local` at **tail** of `zsh/.zshrc` (after `zoxide init`, before `p10k` apply) + `[[ -f $ZDOTDIR/.zshrc.local ]]` fallback. For Neovim: `pcall(require,"local")` at end of `init.lua` or `lua/local.lua` (gitignored) returning optional overrides; document `cp lua/local.lua.example lua/local.lua` pattern. Add to `.gitignore`: `**/.zshrc.local`, `zsh/.zshrc.local`, `nvim/.config/nvim/lua/local.lua`, `nushell/.config/nushell/secrets.nu`, `.env`. Document in README + AGENTS.md. |
| **Self-test / health gates (VM-less validation)** | PROJECT.md validation plan: user tests fresh install in VM; agent must validate locally without VM via self-test. No current `make test` / `just check` (CONCERNS.md: "No automated health gate"). Self-test is the differentiator that lets the installer claim reliability. | MEDIUM | Build `bash setup.sh --self-test` or `bash setup.sh --dry-run --verify` that checks: `stow --no --verbose` symlinks correct (`ls -la ~/.config/nvim/init.lua` → repo), `command -v z && z --version` + `zi` (`zoxide` hooks), `nvim --headless -c "checkhealth" -c "qa"` zero warnings (parse `/tmp/checkhealth.log`), `mason-registry` packages installed (`:MasonInstallAll` sync check), `starship --version` + `zoxide init zsh` hook presence, `PATH` dedup empty, `zsh -i -c "echo loaded"` exit 0. Emit TAP/`ok/not ok` lines. Also reuse `--dry-run` as preview gate. Can run headless in CI or after `git pull`. |
| **Zsh `Ctrl+R` fzf history that actually works (conflict-free)** | Current Zsh pain: no working fuzzy history; `zsh/.zshrc` loads `joshskidmore/zsh-fzf-history-search` then `marlonrichert/zsh-autocomplete` with `bindkey "^I" menu-select` and `^I` remap — ordering breaks both. Users expect `Ctrl+R` like every modern Zsh config (oh-my-zsh, prezto). | MEDIUM | Fix: ensure `fzf` binary installed (add to core deps; Ubuntu 24.04 ships 0.44.1 — warn if <0.48, integrator change `source <(fzf --zsh)` vs old `key-bindings.zsh`). Resolve plugin order: source `zsh-fzf-history-search` **after** `zsh-autocomplete` or remove redundant plugin (choose one history widget). Normalize: `eval "$(fzf --zsh)"` or `source /usr/share/fzf/key-bindings.zsh` fallback + `bindkey '^R' fzf-history-widget` (or `__fzf_history_search__`). Guard with `[[ -f /usr/share/fzf/key-bindings.zsh ]]`. Document conflict resolution in comments. Deferred polish after core installer per PROJECT.md — phase ordering should put installer first, this second. Test: `zsh -i -c "bindkey | grep -q fzf"` + manual `Ctrl+R` smoke. |
| **Neovim which-key leader popup (`<Space>` → nested hints, LazyVim-like)** | PROJECT.md requires which-key. Discoverability is a major UX gap: 14 languages + 21 plugins expose ` <leader>ff/fg/fb/fh`, `sr`, `lz`, `ql`, `e/ep/ec` with no hints. LazyVim users expect `<Space>` to show available combos. | LOW | Add `folke/which-key.nvim` v3 spec: `event="VeryLazy"`, `opts={preset="modern", delay=200, triggers={{ "<auto>", mode="nxso" }}, spec={{ "<leader>f", group="find" }, { "<leader>s", group="search" }, ...}}`. Migration note: v3 breaking change `register()` → `spec` (2024). Provide keymaps with `desc` already in `base/keymaps.lua` — which-key auto-discovers them; just add `group` entries for top-level. Low risk, immediate wow. |
| **Neovim Mason auto-install + cleanup lifecycle** | Goes beyond table-stakes presence: full lifecycle (install on setup, cleanup on uninstall, dedup, debounce) is the polished differentiator vs "run this manual command". PROJECT.md: removal must also clean Mason/packages. Current `utils/mason-install-all.lua` is manual `MasonInstallAll` with `mr.refresh` callback and `WARN` on missing `has_package`. | MEDIUM | Recommended stack: keep `mason-org/mason.nvim` + add `WhoIsSethDaniel/mason-tool-installer.nvim` with `ensure_installed = require("lang").mason_packages`, `run_on_start=true`, `start_delay=3000`, `debounce_hours=24`. Or enhance existing `MasonInstallAll` to support `setup.sh` headless: `nvim --headless -c "MasonInstallAll" -c "sleep 10" -c "qa"` or `mason-tool-installer` sync `check_install(true,true)`. On uninstall (`setup.sh --uninstall` with `nvim` deselected): `rm -rf ~/.local/share/nvim/mason` or `MasonUninstallAll` equivalent + remove `~/.local/state/nvim`, `~/.cache/nvim` optionally. Deduplicate via existing `deduplicate()`; handle `is_installed()` filter before `MasonInstall`. |
| **Theme duplication centralized (single token)** | Hard-coded `catppuccin mocha/latte` duplicated across 4 files (`alacritty.toml` import, `catppuccin-mocha.toml`, `starship.toml palette`, `nushell/catppuccin.nu`, `nvim/colorschemes/catppuccin.lua`) — changing flavor requires 4 edits, currently inconsistent `alacritty mocha vs starship latte`. Centralizing is a clear polish signal. | LOW | Option A (simple, this milestone): create `.theme` or `theme.toml` at repo root (`flavor=mocha`) and have `setup.sh` `sed` or `envsubst` the palette into stowed files at install, or make `starship.toml`/`alacritty.toml` read `THEME` env. Option B (future): adopt `chezmoi`/`yadm` templating — **defer**. Minimal v1: one `THEME` variable + README note + `setup.sh` `apply_theme()` that validates consistency and warns if `starship.toml palette` != `alacritty import`. Keep `tokyodark` active in `settings.lua` until unified. |
| **Hyprland `zsh/.zprofile` guard respecting `server` mode** | Known bug: `if [ -z "$DISPLAY" ] && [ "$(tty)" = "/dev/tty1" ]; then exec start-hyprland; fi` runs even when intending `server` headless, and if Hyprland not installed, login session dies. Nushell path has commented guard; Zsh path unconditionally execs. | LOW | Fix: guard with `command -v Hyprland >/dev/null 2>&1 || command -v start-hyprland >/dev/null 2>&1` and mode flag: stow a marker `~/.config/dotfiles/mode` written by installer (`local` vs `server`) and check `[[ $(cat ~/.config/dotfiles/mode 2>/dev/null) != "server" ]] && exec …`. Or simpler: `[[ -x /usr/bin/Hyprland ]] && [[ ${DOTFILES_MODE:-local} != server ]] && exec`. At minimum, check executable before exec and never die on missing binary (`exec` failure kills login). Document `autostart_hyprland=false` env override. |
| **`telescope-fzf-native` `make` guard + toolchain in core** | Silent perf regression: `cond = vim.fn.executable("make")==1` disables fzf sorter without user warning; `setup.zsh --mode server` on minimal image without `make` triggers fallback. User expects fzf performance. | LOW | Installer fix: add `make`+`gcc` to `common` deps for all modes (not just Arch GUI) — already in `nvim/README.md` but not in `get_deps`. Editor fix: in `telescope.lua`, add `vim.notify("telescope-fzf-native: 'make' not found — falling back to generic sorter; run setup.sh to install build-essential", WARN)` in `cond` else branch or `config` hook, so user sees warning beyond startup status. Self-test checks `command -v make`. |
| **`init.lua` lazy.nvim pin + verification** | Security + reproducibility: `init.lua:4-8` clones `https://github.com/folke/lazy.nvim.git --branch stable --filter=blob:none` without tag/commit pin; `lazy-lock.json` pins `85c7ff3` but bootstrap precedes lock check — drift possible on fresh clone. | LOW | Pin bootstrap to commit/tag: `git clone --branch stable --filter=blob:none … && (cd lazypath && git checkout 85c7ff3)` or switch to `--branch v11.x` tag. Post-clone verification: `git -C "$lazypath" rev-parse HEAD` compare to `lazy-lock.json` `lazy.nvim.commit`, `vim.notify WARN` on mismatch. Keep `vim.uv or vim.loop` + `vim.v.shell_error` + `vim.fn.getchar` guard from official bootstrap (context7 verified). Document pin in `init.lua` comment. |
| **Stow symlink correctness in self-test + docs (Starship folding)** | Subtle `starship/.config/starship.toml` → `~/.config/starship.toml` folding requires `stow starship` from repo root; moving repo or invoking from subdir breaks. `STARSHIP_CONFIG=$HOME/.config/starship.toml` env in Nushell vs actual stow target mismatch is silent. | LOW | Self-test asserts `readlink -f ~/.config/starship.toml` contains `starship/.config/starship.toml`; assert `~/.config/nvim/init.lua` symlink valid; assert repo contains `starship/.config/starship.toml` not `starship/starship.toml`. README must state "run from repo root". |

### Anti-Features (Commonly Requested, Often Problematic)

Features that seem good but create problems — deliberately NOT building in this milestone.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| **Fix Nushell-specific tech debt in this milestone** | Parity instinct: "if we fix Zsh, why not Nushell?" `zoxide` double-hook, `uv.nu` 400-line eager sourcing, `env.nu` secret, init ordering all look fixable. | PROJECT.md explicitly scopes Nushell as **backup only** — "Do not fix Nushell-only concerns: zoxide hook double-registration, uv.nu eager loading, MISTRAL_API_KEY committed, Nushell init ordering". Spending cycles there violates milestone constraints, reintroduces drift (fixing Nushell re-mirrors logic we just unified to Bash), and distracts from Bash canonical path. Re-fixing after Bash proves stable is cheaper. | Document Nushell as backup in README + in-code comments; keep `setup.nu` shim that calls `bash setup.sh` if needed. Defer Nushell QoL to future milestone if Nushell becomes default. |
| **Privileged blind `stow --adopt` or silent keyd overwrite** | Feels convenient to always `--adopt` and `keyd reload` without prompting — "just make it work". | Moves host `/etc/keyd/default.conf` into repo without consent, making rollback ambiguous; a stale or malicious repo `default.conf` hijacks input (CONCERNS.md: "Risk: MITM input handling"). `NOPASSWD` sudoers widening worsens it. One bad adopt on a borrowed machine is unrecoverable. | Explicit conflict check: `stow --no --verbose -t / keyd` preview → `diff` → `Type 'yes'` to adopt. Use plain `stow -t / keyd` when no conflict. Require `keyd` checklist opt-in (OFF by default). Document least-privilege sudoers (`start|stop|reload keyd` only). |
| **Auto-`chsh` changing default shell without confirmation** | "One-command bootstrap should just `chsh` to zsh" seems frictionless. | `chsh -s $(which zsh)` requires password, modifies `/etc/shells`, and can lock users out on minimal images or when `zsh` install failed. Doing it silently breaks headless servers where `bash` is expected. POSIX `chsh` also varies across distros. | Always prompt: `read -q "Change default shell to zsh? (y/n): "` then `which zsh \| sudo tee -a /etc/shells && chsh -s $(which zsh)`. Show current `$SHELL` vs chosen. Make it the last step after successful stow. Document `chsh` manually in README. |
| **Auto-installing all 14 language LSPs synchronously on every Neovim startup** | "True auto-install" — on each `nvim` launch, ensure every `pyright`/`ruff`/`ts_ls`/etc. is present. | Startup gated on network (`MasonInstall` burst, ~500MB parsers linear cost per CONCERNS.md). With 30+ languages, cold start hangs seconds on every open, violates `defaults.lazy=true` philosophy, and hammers Mason registry. Also `lazy.nvim git clone` already blocks startup (performance bottleneck). | Use **deferred** auto-install: `mason-tool-installer` `run_on_start=true` with `start_delay=3000` and `debounce_hours=24` — installs 3s after startup, once per day. Or keep `MasonInstallAll` as explicit `setup.sh` post-stow headless command (`nvim --headless -c "MasonInstallAll"`). Never block `init.lua` synchronously. Split languages into `core` vs `opt-in` tiers for future. |
| **Re-implementing GNU Stow logic in Bash (custom symlink engine)** | "Stow is old Perl; we can write a faster `ln -sf` loop and avoid the `stow` dependency." | Reimplements directory folding, `--adopt`, `--dotfiles`, conflict detection, `.stowrc` ignores, and `--no` preview that Stow 2.4.1 just fixed (ignore-list spaces, Perl 5.40 warning). Custom engine will mishandle `starship/.config/starship.toml` folding and `keyd -t /` privileged target — both fragile areas. Introduces new bug class for zero gain. | Depend on `stow >=2.4.1` (host 2.3.1 → upgrade). Installer only orchestrates `stow --restow`/`-D`/`--no`. Leverage upstream fixes. Pin dependency and verify `stow --version` in self-test. |
| **macOS / Windows / new desktop environments (Hyprland successors)** | "Portability" requests: support `brew` on macOS, `sway`/`GNOME` alongside Hyprland, `waybar` alternatives. | PROJECT.md Out of Scope: "New desktop environments or WMs beyond existing hyprland/waybar/grim/slurp local-mode set — not part of reliability milestone". Adding Brew/DE branches multiplies `gui_modules` matrix combinatorially (already `mode × distro` complexity) and requires device testing not available. | Keep Arch/CachyOS/Ubuntu Linux workstations/servers only. Document limitation. If demanded later, add `tag: core|gui|arch-only` manifest and generate stow commands dynamically — defer. |
| **Full CI pipeline / GitHub Actions beyond local self-test** | "Real projects have CI" — auto-test matrix on `manjaro`, `endeavouros`, Ubuntu runners. | PROJECT.md Out of Scope: "Cloud hosting / CI pipeline (GitHub Actions) beyond local self-test — can be follow-up after installer is solid". ### Dependency Notes

- **Unified installer requires distro detection:** without `ID_LIKE` + `command -v` fallback, installer hard-crashes on derivatives before any feature can run — must be first fix in phase ordering.
- **Checklist requires TUI + manifest:** mode+shell prompts build the candidate list, but checklist is where users override `keyd`/GUI on server-with-GPU or deselect `wofi` on Ubuntu — without `gum`/`whiptail` fallback, non-gum hosts (minimal Ubuntu) have no override UI.
- **Mason lifecycle requires lang aggregator:** `lang/init.lua` deduplicates `mason_packages` from 14 languages; auto-install that bypasses aggregator will miss/duplicate packages and drift from `settings.lua` single-toggle surface (fragile area).
- **Self-test requires everything:** it's the capstone that validates Stow + shell + Mason + PATH + prompt in one headless run — if any upstream is missing, gates are meaningless. Build it last.
- **Theme centralization conflicts with backend migration:** solving duplication with a one-token `THEME` variable deliberately avoids chezmoi/yadm rewrite — picking the heavy backend makes the lightweight fix redundant.
- **Hyprland guard vs keyd safety are independent:** both touch `local` mode but via different paths (`zsh/.zprofile` `exec` vs `sudo stow -t / keyd`); can be fixed in parallel after installer skeleton.
- **Zsh fzf history conflicts with autocomplete plugin:** `marlonrichert/zsh-autocomplete` remaps `^I`/`^R` and expects `zicompinit` ordering; installing history search without fixing load order re-breaks it — fix ordering, not just install `fzf`.

## MVP Definition

### Launch With (v1) — The "VM-testable reliable bootstrap" slice

Minimum needed to claim PROJECT.md Core Value: *fresh clone → `bash setup.sh` → working Zsh+Neovim+desktop on any supported derivative + clean reverse, no manual `stow`/`MasonInstallAll`*.

- [ ] **Unified Bash installer `setup.sh` with install + uninstall + `--dry-run`** — why essential: replaces 4-script drift, is the new canonical entry (Bash preinstalled), required for every downstream feature to have a single place to live. Flags: `--mode local|server`, `--shell zsh|nushell`, `--dry-run`, `--stow-keyd y/n`, `--uninstall`/`--remove`, `--help`. Spine of the milestone; without it nothing else ships.
- [ ] **Distro handling fixed (ID + ID_LIKE + `command -v pacman`/`apt` probe, per-distro dep lists corrected, post-install re-verify)** — why essential: #1 reported crash, blocks Manjaro/EndeavourOS/Mint/Pop!_OS users at step 1. Smallest fix with largest unblock.
- [ ] **Interactive flow: mode → shell (zsh default) → checklist (select/deselect override) → execute** — why essential: user-specified `Mode → Shell only, then manual select/deselect override before any writes`. Without checklist, `local` on server or `keyd` on borrowed machine can't be overridden without code edit. Implement `gum` primary → `whiptail`/`dialog` → `select` fallback.
- [ ] **Shell self-install before stow (ensure `zsh` binary + Zinit clone + optional `chsh` offer)** — why essential: bootstrap paradox on minimal images; without it, stowed `zsh/.zshrc` is dead code. Offer `chsh` last, never silent.
- [ ] **Stow symlink correctness + conflict preview (`stow --no --verbose`, repo-root assert, real-file guard)** — why essential: silent wrong target (starship folding, moved repo) makes users think installer succeeded while prompt/theme is broken. Already has real-file `rm -rf` guard — add preview + assertion.
- [ ] **Keyd `--adopt` safety (pre-check `stow --no -t / keyd`, diff, explicit `yes` before `--adopt`, least-privilege sudoers)** — why essential: only privileged write in repo; current blind `--adopt` can swallow host file. Safety constraint in PROJECT.md.
- [ ] **Hyprland `zsh/.zprofile` guard respecting `server` mode + executable check** — why essential: kills login session on headless `server` that stowed only `nvim`+`zsh` but auto-`exec`es Hyprland on tty1. One-line crash on first login = worst onboarding.
- [ ] **PATH dedup (`typeset -U path`)** — why essential: grows unbounded on reload, triggers completion slowness and `ARG_MAX` risk, visible on every `echo $PATH`. Two-line fix.
- [ ] **Docs updated to Zsh-default + Bash installer (`README.md`, `nvim/README.md`, in-code comments, AGENTS.md)** — why essential: current README still advertises `nu setup.nu` as primary — new users follow stale path. Must flip table to `Default: Zsh | Backup: Nushell` and `bash setup.sh` examples before VM validation. Low effort, high confusion reduction.

### Add After Validation (v1.x) — Polish after core installer is VM-proven

Features to add once `bash setup.sh --dry-run` + `--self-test` passes in a fresh container/VM without crash.

- [ ] **Zsh `Ctrl+R` fzf history (conflict-resolved, `bindkey` normalized, `fzf` in core deps)** — trigger: core installer merged and no longer crashes on deps; Zsh pain is next most visible QoL. Requires installer to guarantee `fzf` present first. Fix `zsh-autocomplete` vs `zsh-fzf-history-search` order + `fzf --zsh` integration.
- [ ] **Neovim Mason auto-install + cleanup on uninstall (mason-tool-installer or enhanced `MasonInstallAll` + `nvim --headless` hook from `setup.sh`)** — trigger: `setup.sh` stow is stable; editor can now hook post-stow `nvim --headless -c "MasonInstallAll"`. - [ ] **Neovim which-key leader popup (`folke/which-key.nvim` v3, `preset=modern`, `delay=200`)** — trigger: Mason auto-install proven; discoverability is independent low-risk plugin add. One spec file under `lua/plugins/which-key.lua`, auto-imported by `lazy.nvim`.
- [ ] **Machine-local gitignored configs (`~/.zshrc.local`, `nvim/lua/local.lua` auto-sourced, `.gitignore` entries, documented)** — trigger: users ask for per-machine overrides or second machine onboarded — isolate differences before they dirty git.
- [ ] **Installer self-test / health gates (`--self-test`/`--verify`: Stow symlinks, `z`/`zi`, `checkhealth` zero warnings, Mason, starship/zoxide hooks)** — trigger: core + QoL in place; gates are the acceptance test for VM validation and future PRs. - [ ] **`telescope-fzf-native` make guard warning + `gcc`/`make` already in core (from v1) surfaced** — trigger: self-test reports `make` missing warning; add `vim.notify WARN` in `cond` fallback so editor tells user, not just status silently.
- [ ] **`init.lua` lazy.nvim pin + `lazy-lock.json` verification** — trigger: observed bootstrap/lock drift on fresh clone or after `lazy-lock.json` update; pin to commit/tag and verify `HEAD` vs lock entry.
