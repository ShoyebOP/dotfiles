# Plan 01-01: Strict-mode entry, arg parsing, and Termux-aware deps resolver

> **As a** user with a fresh clone on Arch, Debian-family, or Termux, **I want to** run one `bash setup.sh` command **so that** my system dependencies resolve and install correctly with no manual package work and no preinstalled Zsh or Nushell.

<objective>
Create the canonical `setup.sh` Bash entry-point with strict-mode guards, full flag parsing (INST-05), Termux-first family detection (DEPS-01), per-family dep tables with `make`+`gcc`+`fzf`+`zsh` in common and a distinct Termux list (DEPS-02), and a verify → install → re-verify lock with dry-run preview and idempotent re-runs plus stow self-upgrade (INST-02 partial for installs, DEPS-03).

Purpose: This is the spine every later slice builds on — without a crash-proof entry and a correct resolver, checklist/stow work in 01-02 has nothing to stand on.
Output: Executable `setup.sh` that end-to-end resolves and (dry-)installs deps for `--mode server --shell zsh` on this host.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv → parse_args | Untrusted operator input crosses here; allowlist validation required |
| /etc/os-release → detect_family | Vendor file sourced into the shell; only token-compared, never executed downstream |
| Installer → package manager (pacman/apt/pkg ± sudo) | Privilege boundary; Termux branch must never cross into sudo |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | install_deps (sudo pacman/apt) | medium | accept | Platform-signed default repos only; this phase adds no custom mirrors, PPAs, or curl-piped installs (ASVS L1) |
| T-01-02 | Tampering | detect_family (os-release sourcing) | low | mitigate | Source the root-owned vendor file, read only ID/ID_LIKE with defaults, whole-token allowlist match; values never interpolated into commands |
| T-01-03 | Spoofing | parse_args (--mode/--shell values) | low | mitigate | Strict value allowlists; bogus values abort with usage before any state change |
| T-01-04 | Elevation of privilege | Termux install branch | high | mitigate | Termux family uses the pkg binary with no sudo prefix anywhere on that path; failing closed — block on high severity satisfied by construction plus fixture test |
| T-01-05 | Denial of service | re-verify abort (half-provisioned host) | low | mitigate | Residue abort names every missing entry with the exact retry command instead of failing silent |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | No registry packages in this phase (Bash builtins plus platform managers only); gate retained for convergence — nothing to checkpoint |
</threat_model>
