# Phase 7 — Neovim Editor QoL Fixes: Context

Locked decisions from the user conversation (2026-11-23). These are NON-NEGOTIABLE.

## Scope

1. **Diagnostics:** Add a shortcut to open the full diagnostic message for the current line. **Do NOT wrap diagnostics** and do not change virtual-text rendering. No `trouble.nvim` install (the float keybind is sufficient).
2. **Stale keymaps:** Remove keymaps that reference plugins which are not installed (`grug-far`, `persistence`, `diffview`, `Trouble`).
3. **Git visualizer (nvim-scrollview):** Move the scrollview git markers to the **far left**, keep gitsigns' native per-line signs, **hide the scrollbar itself**, and leave a thin blank separator cell between the two gutters.
4. **Surround:** Install `kylechui/nvim-surround` (default keymaps `ys`/`ds`/`cs`/visual `S`), update `lazy-lock.json`.
5. **Buffer cycling:** Rebind next/previous buffer from `<Tab>`/`<S-Tab>` to `<C-,>`/`<C-.>`.
6. **Smoothscroll removal:** Remove `opt.smoothscroll = true` as a cosmetic cleanup. Note explicitly: this is NOT presented as a cursor-jump fix.

## Explicitly out of scope

- **Cursor jumping investigation is excluded entirely.** No LSP-detach handler changes, no `lsp-restart.lua` edits, no `showmatch`/`matchparen` changes, no diagnostic procedure for cursor movement. The user rejected all proposed hypotheses; do not revisit them in plans, tasks, verify steps, or docs. If the user later reports the issue independently, that is a separate phase.
- No changes to Mason auto-install, which-key spec, fzf-lua, installer, or shell config.
- No new themes or general Neovim refactor.

## Key facts established during research

- Neovim v0.12.2 installed; deployed `~/.config/nvim` is byte-identical to the repo; no machine-local `lua/local.lua` exists.
- `vim.diagnostic.open_float()` is available; no existing keybind calls it. Built-in hover keybind **already exists**: `K` in normal mode → `vim.lsp.buf.hover` (`lua/plugins/lspconfig.lua:103`). Do not duplicate it.
- `<C-,>` and `<C-.>` are free in n/i/v/x/t modes (verified via `maparg()`); no built-in or plugin mappings use them. blink.cmp claims only `<Tab>`, `<S-Tab>`, `<C-y>`.
- Alacritty has no custom `key_bindings` and `TERM=xterm-256color`; terminal delivery of Ctrl+,/Ctrl+. must be noted as a caveat (test `<C-v><C-,>` in insert mode; add Alacritty binding only if needed).
- nvim-scrollview options verified from official docs: `base`, `column`, `winblend_gui` (opacity when `termguicolors` is on), `signs_on_startup`, `signs_scrollbar_overlap`, `hide_on_text_intersect`/`hide_on_cursor_intersect`/`hide_on_float_intersect`, `hide_bar_for_insert`, `signs_hidden_for_insert`.
- Neovim right-aligns signs in a widened signcolumn; `signcolumn = "yes:3"` is accepted by v0.12 and gives a blank cell between a 1-cell scrollview gutter at column 1 and the gitsigns sign in cell 3. `yes:4` guarantees a blank cell even when a diagnostic and git sign share a line.
- `lazy-lock.json` pins all 39 installed plugins; a new plugin requires a lockfile entry (generated by `:Lazy sync` / `:Lazy install`).
- Dead keymap references: `<leader>sr` (grug-far, `keymaps.lua:25-34`), `<leader>ql` (persistence, `:81-83`), `dv`/`<leader>dq`/`dh` (diffview, `:115-117`), `<leader>xt`/`<leader>xT` (Trouble, `:157-163`). None of those plugins are in `lazy-lock.json` or any spec.

## Acceptance intent

After this phase: every remaining keymap either works or is obviously a built-in; all four user-reported UX gaps are closed; the cursor-jump topic is untouched and unmentioned except that smoothscroll was removed as cosmetic.
