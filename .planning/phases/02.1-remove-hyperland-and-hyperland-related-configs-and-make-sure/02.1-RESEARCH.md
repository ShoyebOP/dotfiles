The good news for planning: workstream A is a fully inventoried, line-anchored deletion task — every occurrence was located by `Read`+`grep` this session and is listed in §Code Examples with verbatim quotes. The only genuinely new logic is (1) making the dep filter respect unticked stow rows for the overlapping names, and (2) a Debian-only keyd manual-build prompt (live-verified: `apt` on noble has no `keyd`).

**Primary recommendation:** Plan as tracer-first coarse work — Plan 1: removal + remnant sweep + `bash -n`/`--dry-run` verify; Plan 2: unified checklist merge reusing backend patterns with the 17-row map; keep `SELECTED_PACKAGES`/`SELECTED_DEPS` as the two downstream arrays (populate both from the single page) to avoid churning `run_stow`/`run_uninstall`/`offer_system_package_removal`.

**When to use:** This phase — it confines the diff to the checklist layer; `run_stow`, `run_uninstall`, `preview_selection`, `strip_termux_disabled`, `_toolchain_ensure_stow`, and `offer_system_package_removal` keep working unchanged.

## Common Pitfalls

### Pitfall 1: Stale "7 packages" strings and list-height caps
**What goes wrong:** `wofi` removed from arrays but `echo "7 packages offered"` strings and `list_height` caps (`-gt 7` clamps in `checklist_whiptail`/`checklist_dialog`) still say 7, breaking the "Final selection (offered N…)" audit lines and cramping the unified page.
**Why it happens:** Count strings are hardcoded in ~9 places (setup.sh:898, 956, 1014, 1046, 1064, 1095, 1117, 1435-1436, 1446-1447), not derived from `${#ALL_PACKAGES[@]}`.
**How to avoid:** Task must enumerate every `7 packages offered` / `offered 7` / `-gt 7` site (grep `7 packages\|offered 7\|list_height` after edit must return empty for package counts) and update caps to the unified row count per backend (whiptail/dialog cap, fzf `--height`, read numbering).
**Warning signs:** `--dry-run` output still prints "7 packages offered".

### Pitfall 2: `gui_list` partition left referencing deleted names
**What goes wrong:** `main()` builds `gui_list` per family (setup.sh:1461) to partition `core_missing` vs `gui_missing` for status display. If `hyprland waybar grim slurp wl-copy wofi` remain in that case statement, the partition silently mislabels (harmless but confusing) — worse, a copy-paste could reintroduce them into an install path.
**Why it happens:** The case statement duplicates the `get_deps` gui arrays instead of deriving from them.
**How to avoid:** Shrink to `arch) gui_list=(alacritty keyd)`, `debian) gui_list=(alacritty)`, `termux) gui_list=()` in the same edit as `get_deps`; verify with `--mode local --dry-run` showing only remaining GUI names.
**Warning signs:** dry-run "Missing GUI deps" line ever names a removed package.

### Pitfall 3: Debian `apt install keyd` via a missed path
**What goes wrong:** keyd reaches `install_deps` on Debian → `apt install -y keyd` fails → hard error mid-run.
**Why it happens:** Post-removal debian `gui=(alacritty)` structurally excludes keyd, but a future-proof explicit guard is cheap insurance (D-06: "Never route keyd through apt on Debian").
**How to avoid:** Keep keyd out of debian `gui=()` (primary) AND make the D-06 prompt the only debian-keyd path; never append keyd to `missing` on debian.
**Warning signs:** `--dry-run` on Debian shows `apt install … keyd`.

### Pitfall 4: Uninstall path still shows the old single checklist
**What goes wrong:** Install path gets the unified page but the uninstall branch (setup.sh:1428-1439, `prompt_checklist` only, no toolchain page) is forgotten — violating D-08 ("for both install and uninstall paths").
**Why it happens:** The two paths call different prompt functions today.
**How to avoid:** Both branches must call the same unified prompt; uninstall's `offer_system_package_removal` candidates must derive from the unified ticked set mapped to dep names (scoped to post-removal set per D-13).
