# Phase 2.1: remove hyperland and hyperland related configs and make sure anything related to hyperland is not installed in local installation - Context

**Gathered:** 2026-09-14
**Status:** Ready for planning

## Phase Boundary

Remove Hyprland and everything Hyprland-related so `bash setup.sh --mode local` never installs anything from the Hyprland/Wayland-capture stack, and unify the two install/uninstall checklists (stow packages page + toolchain page) into a single page where every app the script can install is toggleable — tick means install the app and stow its config if one exists, untick means never install and never stow. Phase 1's `setup.sh` spine, Termux-aware deps, quarantine/post-verify, and DRY_RUN patterns are locked and not re-asked. Phase 2's uninstall `yes`-guard, keyd privileged gate, and Zinit/chsh decisions carry forward. Shell/theme/local polish stays Phase 3; Mason/which-key/self-test stays Phase 4.

## Implementation Decisions

### Removal breadth (hyprland-related set)

- **D-01:** Remove `hyprland`, `waybar`, `grim`, `slurp`, `wl-copy`, AND `wofi` — i.e. everything except `alacritty`/`keyd`. User chose "All except alacritty/keyd" then confirmed "Remove wofi too".
- **D-02:** Hard-delete the removed entries from `setup.sh` `get_deps` arch/debian `gui=()` arrays and the `gui_list` case (~line 1461) plus the `filter_deps_by_selection` comment (~line 228) — no commented-out lines left behind. Git history is the recovery path. — **Reversibility:** reversible — recoverable via `git log -p setup.sh`; no migration needed
- **D-03:** After removal, Arch `gui=(alacritty keyd)`, Debian `gui=(alacritty)`. The Debian keyd asymmetry is INTENTIONAL and kept: verified live on Ubuntu 24.04 (noble, `ID_LIKE=debian`) that `apt` has no `keyd` package (only `ekeyd`/`esekeyd`), while Arch has `pacman -S keyd`. Debian keyd needs a manual build, so it stays out of Debian `gui=()`.

### Wofi stow package fate

- **D-04:** Delete the entire `wofi/` stow package directory (`wofi/.config/wofi/config` + `style.css`) from the repo — not just delisting. — **Reversibility:** reversible — recoverable via git history; no migration needed
- **D-05:** Remove `wofi` from `ALL_PACKAGES` (7→6: `nvim zsh nushell alacritty starship keyd`) and from `GUI_STOW_PACKAGES` (3→2: `alacritty keyd`). Single unified checklist shows 6 clean rows with no wofi mention anywhere (inferred from "Delete directory entirely" + "Gone + unify rest"; the 6-vs-7 follow-up was dismissed, so clean-6 is the working default — planner may flag if the Phase 1 D-09 7-row contract needs explicit updating).

### Debian keyd manual-install prompt

- **D-06:** `keyd` stays in `ALL_PACKAGES` checklist on Debian (only Termux disables it), so a Debian user can still tick it. Since `apt install keyd` would fail (no package), Phase 2.1 must add a Debian-only manual-install prompt when keyd is selected: tell the user keyd is not in apt and point at building from `https://github.com/rvaiya/keyd`, then proceed to the existing privileged `sudo stow -t / keyd` flow only if the `keyd` binary exists. Never route keyd through `apt` on Debian; never silently skip a ticked keyd.

### Local mode redefinition

- **D-07:** Rewrite both `prompt_mode` lines (~line 345). Local is no longer "Full GUI: Hyprland, Alacritty, keyd, etc." — new wording along the lines of Local = desktop extras (Alacritty terminal, Keyd remap), Server = headless (no GUI packages). Hyprland disappears from prompt text, `--help`/`usage()`, and README mode descriptions. Exact strings are planner's choice within that meaning.

### Unified single-page checklist (new scope, user verbatim)

- **D-08:** Merge the two current checklists — page 1 stow packages (`prompt_checklist` over `SELECTED_PACKAGES`) and page 2 toolchain (`prompt_toolchain_checklist` over `SELECTED_DEPS`/`ALL_TOOLCHAIN`, 13 deps) — into ONE single-page checklist shown once before any write, for both install and uninstall paths. User verbatim: "the current install and uninstall setup shows two pages of checklist. but i want all of it to be unified as one single page."
- **D-09:** Every app the script can install/uninstall becomes toggleable on that single page — including the system-dep `gui` extras, which today bypass the filter and are governed by mode alone (`filter_deps_by_selection`: "gui extras bypass the filter"). Mode (`local`/`server`) + shell only set the PRE-SELECTION defaults; the user can toggle any row before any write. User verbatim: "it didn't had the hyperland packages as toggleable. so you shoul unify the selection so every app the setup script has the ability to install/uninstall is toggleable."
- **D-10:** Toggle semantics are strict and uniform: tick = install the app (package manager) AND stow its config if a stowable config exists for it; untick = never install, never stow. Applies symmetrically to uninstall: ticked = remove binary (per Phase 2 D-05 all-packages offer) + `stow -D`; unticked = leave alone. The five-backend ladder (`gum → whiptail → dialog → fzf → read`, Phase 1 D-09..D-12) and cancel-never-cascades contract are preserved — only the row set and single-page shape change.
- **D-11:** The removed Hyprland 6 (`hyprland waybar grim slurp wl-copy wofi`) are gone entirely and do NOT appear on the unified page — not even as disabled rows. User chose "Gone + unify rest" over "Keep as opt-in rows". The single page lists only what remains: 6 stow packages + toolchain deps + remaining gui extras (`alacritty`, `keyd` on Arch).

### Remnant sweep (no binary cleanup offer)

- **D-12:** Delete ALL Hyprland text remnants: `nushell/.config/nushell/env.nu` commented launch block (~lines 21-24: `Launching Hyprland...` / `exec start-hyprland`), `zsh/.zprofile` Hyprland comments (rewrite as neutral empty-login-profile comment with no Hyprland mention), `README.md` GUI package lines + mode/checklist prose + manual stow examples referencing wofi-gui sets, `AGENTS.md` Hyprland-stack lines (stack description, core/GUI dep lists, `zsh/.zprofile` auto-exec rows, `wofi`/`waybar`/`grim`-on-Hyprland dependency rows, stow-package lists). Historical `.planning/` docs are NOT edited.
- **D-13:** Do NOT offer to uninstall Hyprland binaries already on disk from prior installs. User verbatim: "delete all remnants but it should not offer to uninstall those packages." Users remove leftover `hyprland`/`waybar`/`grim`/`slurp`/`wl-copy`/`wofi` binaries manually; `--uninstall` only handles packages in the post-removal set.

### Agent's Discretion

- Checklist 6-row default (D-05): the explicit 6-vs-7 question was dismissed mid-discussion, so clean-6 is assumed. Planner may keep a disabled-row wofi entry instead if the five-backend implementations make full row removal risky — but default is full removal.
- Exact new `prompt_mode` strings (D-07) and unified-page row ordering/grouping headers (stow pkgs vs toolchain vs gui extras on one page) are planner's choice.
- Exact Debian keyd manual-install prompt wording and whether it offers to open the build URL or just prints it (D-06) is implementer's choice, within `--dry-run` preview rules.
